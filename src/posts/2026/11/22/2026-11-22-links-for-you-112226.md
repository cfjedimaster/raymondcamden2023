## Developer Slides

I've been a [Reveal](https://revealjs.com/) user for years. It makes it easy to use HTML to create web-friendly slides. It's great, but I ran across [Slidev](https://sli.dev/) a few weeks ago and it looks like a great alternative. It's Markdown based and has a CLI for scaffolding as well as exporting to PDF, PPTX and other formats. You can even use a built-in interactive editor in your browser. It's been a hot minute since I've given a presentation, but I plan on using this next time. 

## You may not need NPM...

Of course you need it, I'm just being silly. But this great post by [Flavio](https://flaviocopes.com/about/) talks about additions to Node.js that replace common npm packages: [Node.js built-ins that replaced npm packages](https://flaviocopes.com/node-builtins/). He goes through multiple different packages that have built-in support with Node now, but also discusses why you may still want the existing packages. I've said this for *years* now, but with so many npm packages out there it's easy to forget what's available in the platform itself, and Node's certainly been advancing at a rapid clip over the years. 

## Did AI kill web components?

I'm a *huge* fan of web components (you can peruse my [many posts](https://www.raymondcamden.com/tags/web-components) on the topic if you want), but in this post by Nolan Lawson, he argues about their future in an agentic future: [Do web components have a future if nobody is writing them?](https://nolanlawson.com/2026/10/19/do-web-components-have-a-future-if-nobody-is-writing-them/). Nolan is dang smart, and he makes some really good points here. There's a few quotes I think that particularly stand out:

<blockquote>
In short, web components were designed for a world where people typed HTML by hand, code was scarce, and thus reuse was an economic necessity. None of those things are true anymore, or at least they’re much less true and becoming less so by the day.
</blockquote>

And this bit:

<blockquote>
Still, I think the strongest argument of all is that neither web components nor React nor any other framework really matter, except maybe as a footnote in someone’s AGENTS.md or an aside in an agent’s thinking process. Recently I vibe-coded a small app for my wife, and the agent mentioned that it was wavering between Preact and Svelte before finally settling on Preact. To be honest, I didn’t care at all because the app worked and solved the problem at hand.
</blockquote>

I think Nolan is pretty spot on, and it's not a "web components are dead" take but rather, not necessarily the as useful in the agentic era. Definitely read his post, and at the end, he links to a good response post as well: [On writing the custom elements section for Modern Web Guidance](https://castastrophe.blog/on-writing-the-custom-elements-section-for-modern-web-guidance/).
